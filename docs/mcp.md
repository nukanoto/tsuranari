# tsuranari MCP サーバー

LLM から日程調整を作成、取得、更新するための MCP サーバー。実装は `src/mcp.ts` にある。検証と D1 への読み書きは画面用の REST API と同じ `src/events.ts` を使う。

## 接続

| 項目       | 値                                      |
| ---------- | --------------------------------------- |
| URL        | `https://tsuranari.nukanoto.net/mcp`    |
| Transport  | Streamable HTTP (応答は JSON、SSE なし) |
| 認証       | なし                                    |
| セッション | なし (リクエストごとにサーバーを作る)   |

Claude Code では次のように登録する。

```sh
claude mcp add --transport http tsuranari https://tsuranari.nukanoto.net/mcp
```

claude.ai では Settings の Connectors に同じ URL を追加する。

認証がないので、`/mcp` に届く人は誰でもイベントを作れる。イベント ID か URL を知っていれば、誰でもそのイベントを読み書きできる。権限の範囲は Web 画面と同じ。

## 枠の書き方

候補の枠は `YYYY-MM-DD#i` という文字列で表す。`i` はイベントの `slots` の番号で、0 から始まる。`slots` の各要素は `label` (枠の名前) と、あれば `time` (時間帯) を持つ。たとえば `slots` が `[{"label":"午前"},{"label":"午後"}]` のイベントでは、`2026-11-16#1` が 11/16 の午後を表す。授業単位の枠は `{"label":"1限","time":"8:40-9:55"}` のように時間帯を持つ。候補日は `dates` に入っている。

## ツール

イベントを指定する引数 `event` には、ID と URL (`https://tsuranari.nukanoto.net/e/<id>`) のどちらも使える。回答を指定する引数 `response` には、回答 ID と参加者の名前のどちらも使える。名前はイベント内で重複しない。

### `create_event`

イベントを作る。

| 引数              | 必須 | 内容                                                                  |
| ----------------- | ---- | --------------------------------------------------------------------- |
| `title`           | 必須 | イベント名。100 文字以内                                              |
| `creator`         | 必須 | 作成者名。50 文字以内                                                 |
| `start`           | 必須 | 候補開始日 `YYYY-MM-DD`                                               |
| `end`             | 必須 | 候補終了日 `YYYY-MM-DD`。開始日から数えて 100 日以内                  |
| `unit`            | 必須 | 時間単位 (下表)                                                       |
| `mode`            |      | 画面での回答方式。`ng` (× をつける) か `ok` (○ をつける)。既定は `ng` |
| `excludeWeekends` |      | 土日を除外するか。既定は `true`                                       |
| `memo`            |      | 参加者へのメモ。1000 文字以内                                         |

| `unit`                  | 枠                                      |
| ----------------------- | --------------------------------------- |
| `day`                   | 終日                                    |
| `half`                  | 午前、午後                              |
| `hour_0_24`             | 0:00 から 23:00 の 1 時間ごと           |
| `hour_8_18`             | 8:00 から 17:00 の 1 時間ごと           |
| `hour_8_21`             | 8:00 から 20:00 の 1 時間ごと           |
| `half_hour_8_18`        | 8:00 から 17:30 の 30 分ごと            |
| `class_1_6`             | 1 限から 6 限 (筑波大学の時間割)        |
| `class_1_6_after`       | 1 限から 6 限と放課後                   |
| `class_1_6_lunch`       | 1 限から 6 限と昼休み (2 限と 3 限の間) |
| `class_1_6_lunch_after` | 1 限から 6 限、昼休み、放課後           |

### `get_event`

イベント、全回答、ベスト候補を返す。読み取りだけを行う。

| 引数    | 必須 | 内容                                                                  |
| ------- | ---- | --------------------------------------------------------------------- |
| `event` | 必須 | イベント                                                              |
| `with`  |      | ベスト候補の計算に含める参加者 (名前か回答 ID の配列)。省略すると全員 |

### `update_event`

指定した項目だけを変える。引数は `event` のほか、`create_event` と同じ項目をすべて任意で受け取る。

- 回答が 1 件でもあると、`unit` と `mode` は変更できない。既存の印の意味が変わってしまうため。
- 期間や土日の扱いを変えると、候補から外れた枠の印は全員分消える。

### `add_response`

回答を追加する。

| 引数          | 必須 | 内容                                                 |
| ------------- | ---- | ---------------------------------------------------- |
| `event`       | 必須 | イベント                                             |
| `name`        | 必須 | 参加者の名前。50 文字以内、イベント内で重複不可      |
| `comment`     |      | コメント。200 文字以内                               |
| `available`   |      | 参加できる枠の配列。ほかの枠は参加できない扱いになる |
| `unavailable` |      | 参加できない枠の配列。ほかの枠は参加できる扱いになる |

`available` と `unavailable` はどちらか一方だけを渡す。どちらも省略すると、全枠に参加できる回答になる。

保存するときは、イベントの回答方式に合わせてサーバーが `marks` (画面で印をつけた枠) に変換する。`ng` のイベントに `available` を渡すと、それ以外の枠が `marks` になる。LLM は回答方式を気にせず、言いやすいほうで渡せばよい。

### `update_response`

回答を変える。

| 引数                       | 必須 | 内容                                            |
| -------------------------- | ---- | ----------------------------------------------- |
| `event`                    | 必須 | イベント                                        |
| `response`                 | 必須 | 変更する回答                                    |
| `name`                     |      | 新しい名前                                      |
| `comment`                  |      | 新しいコメント                                  |
| `available`、`unavailable` |      | `add_response` と同じ。渡すと枠を全部置き換える |

省略した項目は元の値のまま残る。

### `delete_response`

回答を消す。引数は `event` と `response`。

## 返り値

どのツールも、成功すると変更後のイベント全体を 1 つの JSON 文字列で返す。結果を確かめるために `get_event` を呼び直す必要はない。

```json
{
  "id": "Tr9BCtrGXjYN",
  "url": "https://tsuranari.nukanoto.net/e/Tr9BCtrGXjYN",
  "title": "ゼミ",
  "creator": "三谷",
  "memo": "",
  "mode": "ng",
  "unit": "half",
  "start": "2026-11-16",
  "end": "2026-11-17",
  "excludeWeekends": true,
  "dates": ["2026-11-16", "2026-11-17"],
  "slots": [{ "label": "午前" }, { "label": "午後" }],
  "responses": [
    {
      "id": "kP3x...",
      "name": "佐藤",
      "comment": "",
      "marks": ["2026-11-16#0", "2026-11-16#1", "2026-11-17#1"],
      "updatedAt": "2026-11-12T09:30:00.000Z"
    }
  ],
  "marksMean": "slots the participant cannot attend",
  "selected": ["佐藤"],
  "best": [
    { "slot": "2026-11-17#0", "date": "2026-11-17", "label": "午前", "ok": ["佐藤"], "ng": [] }
  ]
}
```

| 項目        | 内容                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------ |
| `url`       | 人に共有するイベントの URL                                                                 |
| `marks`     | 画面で印をつけた枠。意味は `marksMean` に書いてある                                        |
| `marksMean` | `marks` が「参加できない枠」(`ng`) と「参加できる枠」(`ok`) のどちらを表すか               |
| `selected`  | ベスト候補の計算に含めた参加者の名前                                                       |
| `best`      | 参加できる人が多い枠の上位 10 件。人数が同じなら日時の早い順。誰も参加できない枠は含めない |

`best` の各要素の `ok` は参加できる人、`ng` は参加できない人の名前。`selected` に入っていない人はどちらにも入らない。

## エラー

入力の誤りや見つからない対象は、MCP のツールエラー (`isError: true`) として返す。本文はエラーの説明だけの文字列になる。

| 例                                                       | 原因                                      |
| -------------------------------------------------------- | ----------------------------------------- |
| `event not found`                                        | イベントがない                            |
| `no response matches "佐藤"`                             | 名前か ID に合う回答がない                |
| `unknown slot: "2026-11-14#0"`                           | 候補にない枠を指定した                    |
| `pass either available or unavailable, not both`         | `available` と `unavailable` を両方渡した |
| `同じ名前の回答がすでにあります`                         | 名前が重複している                        |
| `回答があるイベントは時間単位と回答方式を変更できません` | 回答があるのに `unit` か `mode` を変えた  |
| `終了日は開始日以降を選択してください` など              | 作成と同じ入力検証に失敗した              |
